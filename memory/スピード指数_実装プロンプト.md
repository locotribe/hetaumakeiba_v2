## 共通の前提（毎回Claude Codeに守らせる）

以下を各プロンプトの冒頭に付けて渡す：


## フェーズ2：馬場状態（クッション値・含水率）の結合ヘルパー

目的：各走（日付・場）に、その日のクッション値・含水率を紐付ける。

```
lib/logic/analysis/ に track_state_resolver.dart を新規作成。
track_conditions テーブル（date, cushion_value, moisture_turf_goal/4c, moisture_dirt_goal/4c）を参照し、
与えられた「日付＋競馬場」に対応する馬場物理状態を返すクラスを実装する。

- resolve(date, venueTrack, surface): ({double? cushion, double? moisture}) を返す。
  - surface が 芝 → cushion（無ければ null）と moisture_turf を使う。
  - surface が ダ → cushion は使わず moisture_dirt を使う。
  - 日付の完全一致が無い場合は同一週内の最近傍を許容（±3日程度、無ければ null）。
- クッション値・含水率が両方 null の場合の呼び出し側フォールバックは、離散馬場状態（良稍重不）に委ねる想定。

既存 track_conditions リポジトリの読み出しパターンに合わせること。単体テスト（DBモック or 実DBの既知日付）で null/非null両方を確認。
```

検証：既知日付（例：クッション値がある2021年以降の芝、含水率のあるダート）で非null、2019年以前でcushion=null。

## フェーズ3：スピード指数の算出（コア）

目的：`SimulationParamsCalculator` と同じ設計で、スピード指数を算出するクラスを追加。

### モデル & DB（3-1）

```
既存の horse_simulation_params（model + repository + db_provider のテーブル作成 + onUpgrade）を手本に、
スピード指数用の保存先を同じ様式で追加する。

- モデル: lib/models/horse_speed_index_model.dart
  フィールド: horseId, bestIndex(double), recentAvgIndex(double), trend(double),
             confidence(double 0..1), sampleCount(int), calculatedAt(String)
  toMap/fromMap を既存モデルに合わせる。
- テーブル: horse_speed_index（主キー horse_id）。db_constants に定数追加。
- マイグレーション: db_provider の DB バージョンを1つ上げ、onUpgrade に新テーブル作成を追加。
  ※CLAUDE.md改善案の指摘どおり、マイグレーションの例外は握りつぶさず rethrow すること。
- リポジトリ: 既存リポジトリと同じ配置・命名で upsert / getByHorseId を実装。

DB変更はここだけ。既存テーブルのスキーマは変更しない。
```

### 算出ロジック（3-2）

```
lib/logic/analysis/speed_index_calculator.dart を新規作成。
SimulationParamsCalculator.calculate(horseId, records) と同じ入口を持つ：
  static Future<HorseSpeedIndex> calculate(String horseId, List<HorseRaceRecord> records, {TrackStateResolver resolver})

各走ごとに「1走スピード指数」を算出し、馬単位に集約する。

【1走スピード指数（v1：条件マッチ基準）】
  rawIndex = (基準タイム − 走破タイム) × 距離係数 + 馬場補正 + 基準値(80)
  - 走破タイム: parseRaceTime。
  - 距離係数: 距離(m)に反比例する係数表を speed_index_calculator 内に定数で定義
    （短距離ほど大。まずは西田式に準じた妥当な初期値を定数化。後で調整可能なようまとめて宣言）。
  - 基準タイム: その馬が「同一サーフェス・同一距離」で走った過去走から代表値（中央値）を用いる暫定基準。
    ※レース横断の基準テーブルは v2 で導入。まずは馬内比較で破綻しない形にする。
  - 馬場補正: track_state_resolver でクッション値/含水率が取れる場合はそれを、
    取れない場合は離散馬場状態（良=0, 稍=補正, 重, 不）の固定オフセットでフォールバック。

【馬単位の集約】
  - bestIndex   : 1走指数の最大値
  - recentAvgIndex: 直近5走の加重平均（新しいほど重い：指数減衰）
  - trend       : 直近と過去の差（上昇度）。線形回帰の傾き or 直近平均−過去平均。
  - sampleCount : 有効走数
  - confidence  : フェーズ4で算出（暫定 0.5）

records が空、または time が全て欠測の馬は「指数なし」として confidence=0, sampleCount=0 を返す。

計算対象は平地のみ（障害 "障" は除外）。
```

検証：`horse_simulation_params` に既にある16頭で試算し、値域が破綻していない（NaN/Inf無し、bestIndex が概ね60〜120程度に収まる）ことをログ確認。

## フェーズ4：信憑度（confidence）の重み

```
speed_index_calculator に信憑度算出を追加する。confidence は 0..1。

加点要素（重みは定数でまとめて宣言し調整可能に）:
  - sampleCount が多いほど加点（例: 1走=0.2, 3走=0.6, 5走以上=0.9 を上限に）
  - 直近走が新しいほど加点（久々は減点）
  - クッション値/含水率が取得できた走の割合が高いほど加点
減点要素:
  - 全走が障害/距離大幅変動など比較が不安定な場合

confidence は指数の「質」を表し、予想側でスピード指数の寄与度に掛ける係数として使う（フェーズ5）。
既存の指数（テン加速・上がり・スタミナ）には影響させない。
```

## フェーズ5：予想への統合

```
race_simulation_engine.dart（および出走馬分析タブの表示箇所）に、スピード指数を
「既存指数と並列の一因子」として追加する。既存の重み付け・ロジックは壊さないこと。

- 各出走馬の HorseSpeedIndex を取得し、recentAvgIndex を confidence で重み付けして
  総合評価に寄与させる（寄与の重みは定数で宣言、初期値は控えめに）。
- confidence=0（新馬・少走・データ無し）の馬はスピード指数の寄与を0にし、
  既存ロジックのみで評価されるようにする（破綻させない）。
- UI表示は既存デザインを変えず、数値列/バッジの追加に留める（デザイン変更禁止）。

変更は最小差分で。既存の予想結果が回帰しないことを、変更前後で数レース比較して確認。
```

検証：既存重賞数レースで、変更前後の予想出力を比較し、スピード指数を寄与0にすると従来と一致することを確認（後方互換）。

## フェーズ6：新馬・少走馬の調教フォールバック

```
過去走が無い/1走のみでスピード指数が算出できない馬に対し、
training_factor.dart の相対スコアではなく「生ハロンタイムの施設正規化値」を暫定能力代理として使う。

- training_factor.dart 内の施設別基準（baseTimeTarget: 栗東CW83.0/美浦W83.5/坂路53.5/54.0）と
  pbTime のロジックを参考に、絶対差ベースの正規化値を別途算出するヘルパーを追加
  （training_factor.dart 自体は改変しない。新規ヘルパーとして切り出す）。
- この代理値は confidence を低め（例 0.2 上限）に固定し、フェーズ5の統合に流す。
- 新馬（調教すら無い）は寄与0。

これはあくまで欠測フォールバック。既存の調教相対スコア（コンディション軸）とは役割を分けること。
```

## フェーズ7（v2・任意）：クッション値回帰による残差モデル

```
基準タイムを「馬内中央値」から「同コース・同距離プールでの予測タイム関数」に格上げする。
  予測タイム = f(クッション値, 含水率)  … 同コース・同距離の (タイム, クッション, 含水率) を局所加重回帰
  スピード指数 = 標準化(実タイム − 予測タイム)
- 同名レース限定では標本不足のため、関数推定に限り同コース・同距離をプールする。
- クラス差の混入に注意し、少なくとも race_category / base_prize でクラス帯を揃える。
- 非線形（極端に軟らかい側で悪化）を考慮しロバスト化。
- フェーズ3の v1 と差し替え可能なインターフェースにしておく。
```
