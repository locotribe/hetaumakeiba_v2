作成日: 2026-07-29
対象: hetaumakeiba_v2 予想ロジックへのスピード指数導入に関する設計考察
※本ドキュメントは考察・設計方針のまとめであり、実装（コード変更）は含まない。

> **【追記 2026-07-29｜計算式を「案C」に確定】**
> 当初のサーフェス×距離の標準タイム表／zスコア案は破棄。最終方針は

## 0. 結論サマリー

- スピード指数は「走破タイムを条件差を除いて横比較できる1つの数値」に変換したもの。必要要素はほぼ全てDB・既存タブに揃っている。
- 基準タイムは「同レース・同クラス＋同一馬アンカーで狭く作る」のが最適。数を稼ぐための下級戦プールはクラスバイアスを生むため不採用。
- 精度の要は馬場状態の離散区分（良稍重不）ではなく**クッション値・含水率（連続量）**。基準タイムを「表」ではなく「関数（残差モデル）」にできる。
- レース種別で経路を分ける：古馬定例重賞＝レース履歴＋同一馬アンカー／3歳・2歳戦＝各馬の直近指数を持ち込む／新馬＝調教・血統のみ。
- 各馬の指数には**信憑度（confidence）の重み**を付け、「使う/捨てる」の二値ではなく連続的に扱う。
- 調教タイムは、既存計算式の出力（相対仕上がりスコア）は**能力軸ではなく状態軸**なので指数には混ぜない。生ハロンタイムは施設正規化すれば**新馬・少走馬の欠測フォールバック**として低信頼の能力代理に使える。

## 1. そもそもスピード指数とは

走破タイムは距離・馬場・その日の時計の速さが違えば比較できない。それを補正して1つの数値にするのがスピード指数（西田式が代表）。

```
指数 =（基準タイム − 走破タイム）× 距離指数 + 馬場指数（+ 斤量補正）+ 基準値(80)
```

構成要素（＝導入チェックリスト）:

- **基準タイム**: コース×距離ごとの標準タイム
- **距離指数**: 秒を点数に換算する係数（短距離ほど1秒の価値が大きい）
- **馬場指数**: その開催日に時計が速かった/遅かったかの補正（当日の全馬タイムの基準からのズレ平均）
- **斤量補正**: 斤量差の調整

## 3. 基準タイムの設計

### 3-1. 「10年平均」が不適な3つの別要因

- **高速馬場化（連続的ドリフト）**: 芝を中心にタイムが年々わずかに速くなる。10年平均は基準を遅い側に置き、近走の識別力を失わせる。
- **コース改修（不連続な断層）**: 京都(2020–23全面改修)など。改修前後は別物で、混ぜると基準が壊れる。→ 期間の切断が必要。
- **年次の馬場造園変動（中周期）**: 芝張替え・路盤更新・含水管理方針。→ 重み付けで吸収可。

芝は改修・馬場管理の影響が大きく高速化も顕著、ダートは相対的に安定。recency減衰率はサーフェス別に。

### 3-2. 情報を「絞る」方針（数を稼がない）

- 競馬予想には正解が無いため、基準は「真である」必要はなく**レース間・年次間でスケールが一貫**していればよい。
- 同コース・同距離でも**下級条件戦を混ぜるとクラス依存のバイアス**が入る。これは平均で消えない系統誤差で、小標本ノイズ（分散）より悪い。→ 分散よりバイアスを嫌い、**同レース・同クラスに限定**する。
- 「情報を絞ると信憑性が上がる」はこの文脈で統計的にも妥当（バイアス最小・解釈可能）。

### 3-3. 同一馬反復＝スケール較正の「連結ピン」

- 去年・一昨年も同じレースを走った馬は、異なる年のレースを同じスケールに繋ぐ**校正ブリッジ**（Timeform等のレーティング連結と同原理）。
- 実データで確認済み: 古馬定例重賞は反復多数（マーチS 30頭、平安S 28頭、阪神牝馬S 22頭、大阪杯 19頭、クイーンS 18頭）／3歳戦は反復0頭（オークス・ニュージーランドT・チャーチルダウンズC）。
- 大きなプールモデルを組まずに「レースをまたぐ一貫性」を担保できる。

## 4. 馬場状態はクッション値・含水率で（精度の要）

### 4-1. データ実態（確認済み）

- **クッション値**: 2020年以降・芝のみ（2021年から完全収録、範囲5.4〜12.2、平均9.27）。2020年より前は無し → 直近重視方針と完全一致。
- **含水率**: 全年・芝ダート両方が完全収録（`moisture_turf/dirt` の goal・4c）。

→ 芝＝クッション値（＋含水率）、ダート＝含水率。

### 4-2. 連続量が優れる理由

「良」は幅の広いカテゴリ（クッション値で概ね9〜12）。良/11.5と良/9.0では時計が大きく違う。連続量で条件付ければ、このカテゴリ内分散を消せる（情報量として厳密に上位）。

### 4-3. 本質的な設計転換：基準タイムを「表」から「関数」へ

```
予測タイム = f(距離固定, クッション値, 含水率)   ← 同コース・同距離データから回帰/近傍加重で推定
スピード指数 = 標準化(実タイム − 予測タイム)
```

- 出馬表タブが各過去ラップを「そのときのクッション値・含水率とセット」で表示できる＝学習ペア `(タイム, クッション, 含水率)` は既にアプリ内で組み上がっている。
- 技術的要点:
  1. **標本分断への対処**: クッション→タイムの関数推定に限っては同名レースに縛らず、同コース・同距離をプールして点数を稼ぎ、対象レースの基準は「今日のクッション値でのモデル予測値」を使う。
  2. **非線形性**: 極端に軟らかい側で悪化。単一係数でなくロバスト回帰／局所加重（LOWESS的）。
  3. **馬場指数との二重化**: クッション/含水率は当日の速さを直接読める（全馬タイムから推定不要）。ただし1日1回・点測定で開催中の乾き（特にダート）を捉えきれないため、**全馬タイムからの日次補正を独立した第二推定として残し、両者を突き合わせる**。
  4. **欠損フォールバック**: クッション値null（約920件）→含水率→離散馬場状態、の段階フォールバック。

## 6. 指数の使い方：信憑度の重み

「使う/捨てる」の二値でなく、各馬の指数に**信憑度（confidence）**を付与する。

- 加点要素: 同レース反復あり・同クラス・クッション値あり・近走・標本数多い
- 減点要素: クラス不一致・クッション欠測・久々・少走
- 予想はこの重み付きで指数を使う → 「情報を絞ると信憑性が上がる」を連続的な重みとして符号化。狭い高信頼データを主役にしつつ、薄い場合も破綻せず劣化させられる。

## 7. 調教タイムの位置づけ（計算式を確認済み）

対象コード: `lib/logic/analysis/historical_match_engine_factors/training_factor.dart`（`TrainingFactor.evaluate()`）

### 7-1. この計算式が測っているもの

7軸100点満点 → −5.0〜+10.0 に変換。中身は**「今回の出走メンバー内で調教の仕上がりが良いか」の相対スコア**。

- 軸1・軸2が決定的: `zTime = (evalTime − raceMeanTime) / raceSdTime`（基準＝今回メンバーの平均・標準偏差、同コース・±21日）。→ 相手が変われば点が変わる＝**能力の絶対値でなく相対的な仕上がり（コンディション）**。
- 軸3〜7（PB到達度・年齢による終い劣化・ラップ加速/失速・1週前仕上げ・調教量）＝すべて状態・順調度の評価。
- 速さの絶対水準は施設別固定基準（栗東CW 83.0／美浦W 83.5／坂路 53.5・54.0秒）に対する相対のみ。**調教当日の馬場状態は未補正**。

### 7-2. スピード指数観点の判定

- **(A) 出力スコアをそのまま指数に混ぜる → 不可**。能力軸でなくコンディション軸で二重計上になり、相対値ゆえ指数の一貫性を壊す。**指数とは独立の「状態」ファクター**として現状のまま歴史マッチ側に置くのが正しい。
- **(B) 生ハロンタイム（f6/f4/f1）を能力代理に → 条件付きで可・低信頼**。施設・コース種別で正規化すれば絶対的速さの代理になるが、(1) 厩舎の意図で調教強弱が変わりレースタイムとの相関が弱い、(2) 追い切り馬場未補正、の2ノイズで単独では低重み。

### 7-3. 真価が出る場面

race履歴も同一馬アンカーも無い**新馬・少走馬**では指数が計算不能。その馬にも調教タイムは存在するため、

> 新馬・少走馬に限り、施設正規化した絶対調教タイム（f6/f4 を施設基準との差で標準化）を、暫定的な能力代理としてスピード指数の欠測フォールバックに使う

既存コードの `baseTimeTarget`（施設別基準）と `pbTime`（パーソナルベスト）が、この正規化の種になる（相対スコア化せず絶対差のまま取り出す）。

## 8. 実装フェーズに向けた作業の切り分け（参考）

1. 正規化: time("2:04.8"→124.8s)／distance("ダ1800"→(ダ,1800))／horse_weight／carried_weight／venue(回・場・日目)。
2. クッション/含水率の日付結合: `track_conditions` を各走の日付・場に紐付け。
3. 残差モデル: 同コース・同距離プールで `予測タイム=f(クッション,含水率)` を局所加重推定。
4. 指数算出: `標準化(実タイム − 予測タイム)` を各走に付与。
5. レース種別判定 → 基準経路の切替（古馬定例重賞／3歳・2歳／新馬）。
6. 馬ごと集約: 最高指数・近走平均・上昇度・条件別（距離/馬場/コース別）。
7. 信憑度の重み付与。
8. 新馬・少走馬フォールバック: 施設正規化した絶対調教タイム。
9. 検証: 馬場指数（全馬タイム由来）とクッション値由来の当日速度を突き合わせ、乖離を警告。

## 8.5 追記（2026-07-29｜netkeibaタイム指数の調査を反映したロードマップ示唆）

- **条件別の指数プロファイル**（コース/距離別に指数を集約し「今回条件で高指数を再現できるか」を可視化）：
  将来の集約値拡張候補。

## 8.6 追記（2026-09-03｜バックテスト結果＝フェーズ6・アプリ内ハーネス）

フェーズ6でアプリ内バックテスト・ハーネス（隠しデバッグ画面＋UI非依存の SpeedIndexBacktestRunner）を実装し、
実DBコピー（emulator_backup）に対し読み取り専用で全2,000レース（isEligibleRace通過分、リーク防止＝asOf以前・
対象レース自身を除外して都度算出）を検証した。主指標は「生 positionScore 昇順＝シミュ着順」対「実着順」の
tie対応スピアマン ρ。あり／なしは speedIndexParams のみの差（他入力は完全同一）。

### 結果サマリ（主指標＝生スコア）
- 全体（2,000R）: ベース ρ=0.3715、指数あり ρ=0.3715、**Δρ=−0.0000254（実質ゼロ・わずかに悪化側）**。
  Δρ>0 レースは 2.0%、表示隊列が変化したのは 4.2% のみ。
- **confidence帯別が決定的**: confidence<0.3 が **全体の95.5%（1,910R）**＝ほぼ全レースで指数が信用されず、
  配線の `speedDelta × confidence × 0.15` の confidence 倍率で打ち消されている。
  0.3–0.6（76R）Δρ=−0.0008、**>0.6（14R）Δρ=+0.0052（全体の約200倍・Δρ>0率28.6%）**。
  → confidence重み付けの設計は方向として正しい（信用できる時だけプラスに効く）が、DBが各馬少走のため
    信頼度がほぼ上がらず指数が眠っている。
- ペース別: **ハイ（47R）Δρ=+0.0034・Δρ>0率17%**、スロー/ミドルは0〜わずか負。消耗戦ほど地力=速度が効く。
- 距離帯別: **ダ~1400 +0.0020 / ダ1800+ +0.0012 が正、芝は0〜わずか負**。導入案8.5の
  「ダ・短距離は重視、芝長距離は鵜呑みにしない」を実データが支持。

### 判断
- **今の0.15配線は予想精度をほぼ動かしていない（無害だが価値も未発現）。** リリースの目玉にはまだできない。
- ボトルネックは「0.15の大きさ」ではなく **confidenceがほぼ全レースで低いこと（構造・データ不足）**。
  単純な係数増では伸びにくい（confidence律速）。効くのは「ダート・ハイペース・高信頼」に集中。
- 最優先は従来どおり **フェーズ7（当日馬場差＝クッション値・含水率）**。単体相関0.21が控えめな主因もこれ。
  今回の追加学習＝「フェーズ7に加え、confidenceが上がらない構造問題もある」。

### 次アクション（確定）
1. **天井診断（1回）**: confidence=1.0固定（sampleCount>0の馬のみ）でΔρを測り「指数を全面信用したら効くか」を判定。
   併せて係数掃引（0.15/0.30/0.50）を全体＋効くサブグループ（ダ・ハイペース・高信頼）で。
   - 天井でΔρが明確に正→筋は良い。律速はデータ/confidence。フェーズ7＋confidence設計/蓄積で伸ばす。
   - 天井でもΔρ≈0→展開予想には効かない。深追いせずフェーズ7に集中。
2. その結果を本メモに追記 → フェーズ7へ。

## 8.11 追記（2026-09-04｜バリュー検出も不成立＝スピード指数プロジェクトの総括）

案B（指数×オッズ乖離のバリュー検出）をPythonで検証（196レース・1836頭・リーク防止・クラス中立指数）:
- 市場(人気)→着順 平均ρ=0.36（強い）／ 指数→着順 平均ρ=0.14（弱い）。
- **部分回帰(着順~人気+指数): 指数の寄与≈−0.018（実質ゼロ・逆符号）** → 人気(オッズ)を制御すると指数は着順予測に何も足さない。
- バリュー・バケット: 「指数上位3位以内×8番人気以下」複勝率9.8% vs 8番人気以下全体10.7%（**上振れ−0.009**）。
  指数が推す人気薄はむしろ僅かに走らない＝バリュー検出は不成立。
- 変量補正(+0.019)を足しても市場のρ0.36には遠く、部分回帰の≈0は覆らない。

### 総括（スピード指数プロジェクトの結論）
3つの独立検証がいずれも否定的:
1. 展開シミュに足しても効果なし（フェーズ6: sim Δρ≈0、天井でも≈0）。
2. 当日トラック変量で指数を磨いても、クラス中立の実条件では +0.019 と小さく、simでは≈0の見込み（§8.10）。
3. 指数はオッズを超える独立情報を持たない（バリュー検出不成立、本節）。
→ **現データ規模・この予想アプリにおいて、スピード指数は予測価値をほぼ足さない**と結論。
根因: (a)DBが各馬少走で指数がノイジー・低confidence、(b)基準タイム残差の9割がレース間ノイズ、
(c)市場(オッズ)が既に能力を効率的に織り込み済みで、弱い能力代理は増分情報を持たない。
