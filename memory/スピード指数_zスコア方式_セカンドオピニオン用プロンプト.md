# 別LLMへの確認プロンプト（スピード指数の計算式選択：zスコア方式でよいか）

以下をそのまま別のLLMに貼ってください。

---

あなたは競馬のデータ分析と統計モデリングに詳しい専門家として、以下の設計判断をレビューしてください。
結論ありきの同意ではなく、リスク・盲点・追加で確認すべき材料を率直に指摘してほしいです。

## 背景とゴール

日本の競馬予想アプリ（個人開発・Flutter＋ローカルSQLite）に「スピード指数」を導入したい。
目的は、各出走馬が過去に走ってきた一走一走のタイムを、距離・競馬場・馬場状態の違いを補正して
**1つの比較可能な数値（絶対指数）に変換**し、予想の一因子として使うこと。
重要な前提：これは競馬予想であり「正解ラベル」は存在しない。基準は"真"である必要はなく、
"レースをまたいで一貫"していればよい、という立場。

## 手元にあるデータ（SQLite）

- race_results: 1,021レース。各レースの全出走馬のタイム・着順・上がり3F・通過順、レース全体の
  ラップタイム（前後半・累計）を保持。1レース約15頭ぶんの個別タイムが取れる。
- horse_performance: 1,624走 / 125頭。1走ごとに time, distance(例"芝2400"), track_condition(良/稍重/重/不良),
  agari(上がり3F), pace(前後半), corner_passage(通過順), carried_weight(斤量), horse_weight, venue(例"1東京5") を保持。
- track_conditions: 3,356日ぶん。クッション値(2020年以降・芝のみ、範囲5.4〜12.2)、含水率(全年・芝ダート)。
- データは直近に偏っている（近年ほどレース数が多い）。日本競馬は年々高速馬場化しており、
  競馬場の改修（例：京都2020-23全面改修）による時計の断層もある。

## 基準タイムのデータ被覆状況（実測）

- 「競馬場×サーフェス(芝/ダ)×距離」の勝ち時計中央値（良馬場）が取れる組合せ数:
  n≥5 が44組 / n≥3 が62組 / n≥1 が83組。
- 例：ダ1800の勝ち時計中央値は 中山113.1s / 京都112.2s / 中京112.7s と競馬場ごとに約1秒違う。
- 東京芝2400は17レース（中央値144.0s）取れる。

## すでに決めた設計方針

- 基準タイムは階層構造：競馬場×距離を主、サンプルが薄い組合せはサーフェス×距離で補完。
- 馬場状態(良/稍重/重/不良)は補正で扱う。クッション値・含水率を使った回帰は後続フェーズ(v2)。
- 各馬について 最高指数・直近加重平均・上昇度(トレンド)・信頼度 を算出し永続化。
- 3歳限定戦など過去に同一馬がいないレースは、各馬自身の過去走の指数を持ち込む方針。

## 迷っている点：1走を指数化する「計算式」の選択

### 案A：西田式ライクの線形式
```
指数 = (基準タイム − 走破タイム) × 距離係数 + 馬場補正 + 80
```
- 距離係数（点/秒。短距離ほど大）を手で定義する必要がある。透明で伝統的だが係数が恣意的。

### 案B：zスコア標準化（現在こちらに傾いている）
```
指数 = 80 + ((μ − 走破タイム) / σ) × 10
```
- μ, σ は各「競馬場×距離×馬場」の走破タイム分布の平均・標準偏差。
- σが「その条件で1秒がどれだけ効くか」を自動決定するため、手作りの距離係数が不要。
- 既存アプリの調教評価ロジックが全馬相対の同じzスコア方式を採用済みで、実装様式が揃う。
- 全馬タイム(field全体)が使えるので、東京芝2400なら17レース×約15頭＝250超の標本でμ・σが出せる。

## 質問

1. この用途（正解のない競馬予想で、過去走を横比較する絶対指数）において、案Bのzスコア方式は
   案Aの線形式より適切か。あなたの推奨と理由は。
2. 案Bの具体的リスク・盲点は何か。特に:
   - μ・σを「勝ち時計」でなく「全馬のタイム分布」で取ることの是非（クラス構成・頭数・展開の影響）。
   - 組合せ（競馬場×距離）ごとにDB内のクラス構成が違うことによる、組合せ間のスケール不一致。
   - 薄い組合せでのσ不安定。何レース／何サンプルを最低ラインにすべきか。
   - 馬場状態を「別補正」にするか「μ・σを馬場別に分ける」か、どちらが妥当か。
   - 高速馬場化・改修の断層を、μ・σの算出にどう織り込むべきか（直近重み・期間切断）。
3. 案A・案B以外に、この目的により適した第3の方式はあるか（例：分位点ベース、混合効果モデル、
   ペース/上がり補正の併用など）。
4. 「正解がない」中で、この指数の妥当性を事後検証する現実的な方法は何か
   （例：人気や着順との相関、後のレースの的中との関係など）。
5. フェーズを分けて実装する場合、v1で最低限やるべきことと、v2以降に回してよいことの線引き。

批判的に、かつ実装可能性を踏まえて回答してください。追加で必要な情報があれば指摘してください。
